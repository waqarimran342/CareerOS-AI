The application is layered into four internal modules plus a thin HTTP entry point:
- `src/main.py` exposes three FastAPI routes (`/`, `/health`, `POST /api/analyze`) and converts domain exceptions to HTTP status codes; it also serves the single static `index.html` frontend.
- `config.py` defines a singleton `Settings` class loaded from environment variables (with `.env` auto-loaded via `python-dotenv`), centralizing all secrets and runtime knobs.
- Two data-service modules isolate external I/O: `github_service.py` calls the GitHub REST API, builds a compact profile dict and an `evidence_text` block consumed by agents; `resume_service.py` extracts text from uploaded PDFs via `pypdf`.
- `qwen_client.py` wraps the `google-generativeai` SDK in a `GeminiClient` that enforces strict JSON output through shared prompt rules (`SHARED_JSON_RULES`) and a retry loop that re-prompts the model once if parsing fails; all LLM calls go through this single adapter so the underlying model can be swapped.
- `agents.py` defines five agent classes (`ResumeAnalysisAgent`, `GitHubEvidenceAgent`, `JobMatchingAgent`, `SkillGapAgent`, `MasterCareerAgent`) each exposing a uniform `run(...)` method returning a `Dict[str, Any]`; `run_full_analysis()` orchestrates them in a fixed DAG — resume and GitHub agents run independently, then job matching and skill gap consume their outputs, and finally the Master agent synthesizes the final report.
Dependency direction is strictly inward: `main.py` → `agents.py` + services → `qwen_client.py` + `config.py`; services never import agents, and agents only depend on the LLM client.
