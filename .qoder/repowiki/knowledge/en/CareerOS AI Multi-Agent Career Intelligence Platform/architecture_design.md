The application is organized as a thin FastAPI HTTP layer (`src/main.py`) exposing `/`, `/health`, and `POST /api/analyze` (multipart form upload of a PDF resume plus GitHub username, target role, and optional job description). Configuration is centralized in `config.py` via a single `Settings` object loaded from environment variables (with `.env` auto-loaded from the project root). External data sources are isolated in two services: `github_service.py` fetches public profile/repo data from the GitHub REST API and builds an LLM-friendly `evidence_text`, while `resume_service.py` extracts text from uploaded PDFs using `pypdf`. The core business logic lives in `agents.py`, which defines five specialized agent classes (`ResumeAnalysisAgent`, `GitHubEvidenceAgent`, `JobMatchingAgent`, `SkillGapAgent`, `MasterCareerAgent`) each implementing a `run()` method that calls `QwenClient.chat_json()`. A `run_full_analysis()` orchestrator composes them in a fixed dependency graph: resume and GitHub agents run independently, then job matching and skill gap agents consume their outputs, and finally the Master agent synthesizes all results. `qwen_client.py` wraps the OpenAI SDK pointed at Alibaba Cloud Model Studio's OpenAI-compatible endpoint, enforcing strict JSON output via shared prompt rules and a retry loop that re-prompts the model if parsing fails. Error propagation uses domain-specific exceptions (`QwenError`, `GitHubError`, `ResumeError`) raised inside services and converted to appropriate HTTP status codes in the FastAPI handlers. The frontend is a single static HTML file served directly by the app with no build step.
